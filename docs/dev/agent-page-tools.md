# Native Page tools

This is the first source slice for [#249](https://github.com/EnzoTironi/zoen-native/issues/249), within the unfinished creation workspace work in #179/#175. It adds no App, worker, model permission or document store. The ordinary agent host offers native tools for ordinary Pages in the source conversation. DeckCraft retains schema1 and its existing worker/command bytes; Page uses the same signed ToolProposal envelope with a closed schema2 native binding. Older clients retain the signed log but refuse the unsupported projection.

## Read and propose

`read_page_<artifact hash>` returns the published PageSession shadow, ordered blocks, published version/prefix fingerprint and semantic content hash. It does not return the live editor draft or input capture. A missing/unverified blob, an optimistic or failed Page publication, broken Space integrity, changed source or missing current account/device/member access refuses the read. The snapshot is bounded to 64 KiB of JSON.

`replace_page_block_<artifact hash>` accepts the exact observed artifact, version, prefix, content hash and complete before/after block. The first slice replaces **text only**: block identity, structure, formatting spans and sibling order/content must remain unchanged. Unknown fields, unchanged commands, invalid native edits and arguments over 32 KiB are refused. Reviewed before/after text is retained in the existing request detail; the full request route displays it without the compact card's line limit. No normalization or truncation changes the approved command.

Normal Gate evaluates the call and its user-facing arguments. The existing typed public-reference port classifies only the native-verified artifact locator and exact Page CAS fingerprints; it retains before/after text, formatting and every semantic argument. A mismatch falls back to the complete raw call. A default-false ToolHost policy can require native review only after Gate Allow. The Page write uses that policy with `native:review-required`; Gate Block remains Block and an existing Gate Ask is not asked a second time. This first delivery deliberately requires canonical **ApproveOnce even under Act**. It does not promise future autonomous Page writes. Page reads follow the ordinary Gate and native read access. No `app:<id>` Act grant is created or borrowed for a Page.

## Publication and recovery

The existing certified Agent/device, owner proof, Space membership/writer rights, grants/Block and exact signed source are checked at the relevant read, stage, approve, execute and recovery boundaries. Version/prefix and materialized shadow content/before-block form the local observed-prefix fence for a fresh write. The relay does not provide a global server CAS: an already signed peer publication can be ordered before this publication, and the native CRDT then merges both. A Page with an active input binding/capture, private draft, pending/failed publication or extra unpublished CRDT history is not an agent write base. Even a human edit reverted to identical visible text is refused if its Loro version differs from the published shadow: private operations must not hitchhike in an agent publication.

One Client lock and the existing Engine savepoint enclose native apply, signed ItemVersioned publication, blobs/outbox and the encrypted Page journal. A cached PageSession is detached before append/reload. On rollback it is dropped, never reinserted with rolled-back state. There is no intermediate accepted private agent draft or blind `page_commit` of another editor's work.

The existing bounded encrypted edit receipt gains an optional publication binding: exact intent, actor/device/Space, observed published base, local applied content hash, CID and signed event-intent digest. The result distinguishes `observedBaseVersion` and `appliedContentSha256` from the separately observed `currentVersion`; it does not label the local optimistic ordinal or hash as the eventual canonical publication ordinal or merged hash. Fresh receipts without this extension keep their prior serialized form. Command identity binds the source and reviewed base/arguments. A repeated accepted command returns the same publication, including after restart or a later Page head; it never executes again. Queued, Confirmed, Refused and Unknown are distinct results. A missing, evicted or inconsistent receipt with an old base fails closed instead of minting a replacement publication. No permanent/global deduplication claim is made beyond the existing bounded receipt and authenticated history.

Completed continuation results are rederived from exact historical shadows and linked publications, with current authority checked again. Cached strings cannot authorize effects. Previously completed prefix bytes remain the signed original continuation's context. The normal host's persistent continuation budgets, retries and source behavior are unchanged; no new request, task or approval is synthesized to repair an ambiguous outcome.

## Qualification boundaries

Source tests use synthetic independently keyed owner/Agent identities and real signatures, native PageSession/store APIs and SQL failure triggers. They cover denied/cancelled/expired approval, current source/device/role/Block/head changes, drafts/input/private reverted history, rollback, exact old-history reads, queued/ACK, concurrent peer-before-own-ACK merge and cold same-CID recovery, lost-result cold recovery and forged/missing receipt context. They do not qualify real provider inference, iPhone geometry, remote service status or the full workspace product.

Active/Paused/Revoked remains the normal host/server remote status boundary used by DeckCraft. This slice adds no shadow status store and does not claim instantaneous relay revocation during an already running turn. Actual relay/runtime revocation, two-device concurrent native editing, native full review/history/restore and provider qualification remain part of the later integrated acceptance. Blob writes are inside the reused outer transaction; only actually exercised fault branches may be reported as runtime-tested in the source receipt.

When stacking the independent `agent-host --source` change, retain its selection checks before and after Page discovery/read/stage/approved execution/recovery, including Page-specific early returns. Core source binding is independent and remains mandatory.
