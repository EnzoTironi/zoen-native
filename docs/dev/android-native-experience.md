# Native Android experience and upstream references

This follow-up replaces the eight-second raster mascot loop with native Android Canvas drawing. The Kotlin rig includes all eleven original poses, three head moods, continuous procedural time, drawing entrance and the original line geometry. The working head follows actual agent work. Animation pauses when the view is hidden, loses window focus, leaves the resumed lifecycle or the Android animator scale becomes zero. Static reduced-motion art is fully drawn. Native frames are scheduled after drawing the window so expensive art cannot continuously occupy the UI loop.

Cards now render the five original animated ink drawings (pot, ballot, notepad, trip and hike) using the same on-device renderer; 50 reference frames generated by running the original Swift cover entrance, loop boundaries, reduced-motion time and frozen widget time. Pet pixels and colors are exported directly from the original Swift sprite, including blinking/sleeping/released states. Live art pauses off screen, while static launcher widgets render the frozen original art. The globe cards use the real land contours and native projection.

Donkey Dash uses the original world units, gravity, increasing speed, cactus collisions, carrot collection and original walking sprites. The run is retained through activity recreation and pauses in the background. Jump and pause/resume are exposed to TalkBack as well as touch. The completed run submits its score through the real mini-app tool and signed shared log. Pet feeding animates after published fullness increases, and emotes use the original local-only interaction with native selection feedback. Their palette opens and closes with a reduced-motion-aware transition and wraps all five buttons on narrow displays. Native Care, Play and Leaderboard tabs share the live pet state and stored scores. The first-adoption reveal uses the original ink box and native donkey, can be skipped, persists per pet and observes reduced motion. Score and recovery messages sit above the measured pet navigation and page save controls, preserving real touch access while feedback is visible. Night backgrounds use light heading and navigation text; care controls have adaptive Material surfaces so the gradient cannot hide their labels.

The primary controls use the original 35 ink glyphs, with their signature motion beats, line wobble during interaction, selection draw-on and RTL mirroring for Back and Send. Android Material controls retain their touch targets, ripple, semantics and adaptive navigation. Files and Activity remain primary Android destinations alongside Chats and Store.

Haptic feedback uses `View.performHapticFeedback` with platform effects and API-level fallbacks. It respects system and view settings. Text and voice sends signal after signed storage; recording start, lock, cancellation, tile pickup, reorder, drop and confirmed unpin use their actual action states. Swipe gestures signal the threshold and return with a spring. Mini-app flips observe reduced motion live, including when closing.

Activity opens the native approval deck from the current iOS review, with a retained list view. Long cards and enlarged text scroll vertically for reading; explicit full-width decision buttons remain reachable at 200% font size. Enlarged navigation gives the selected destination enough label space while retaining all four accessible destinations. Right and left decide one request; up and down create the shared engine's scoped, revocable standing rule. Sensitive requests disable standing approval. Buttons and accessibility actions offer the same decisions. A 4.5-second undo window precedes the signed write, survives activity recreation and cancels without a compensating event. Cards follow the finger, return with a spring, fly out after acceptance and slide back on undo. Confirmation feedback follows actual storage. Leaving Activity commits the pending choice; changing accounts or losing keys discards an unsigned choice.
