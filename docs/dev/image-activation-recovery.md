# Images activation recovery

Images retains one encrypted, inert activation intent after the original native stage is Ready and before SQL authorizes maintenance. The intent binds the original Prepared checkpoint, previous/target capsule roots, exact record bytes, exact signed Publish wire, record prior hash and source frontier. Larger sealed record and wire values are retained separately, each bounded below the FDB value limit. They are not provider or financial permissions.

A cold host may recover the same activation when FDB remains at previous and SQL is either previous or exactly next. The external anchor must still retain that exact Prepared. Recovery acquires the existing device lease, refuses the old fence, reads/authenticates every retained capsule chunk and manifest, and checks the original record prior and unchanged source frontier. It then obtains a new, expiring NativeActivation from the current SQL directory and certificate. SQL either applies the original checkpoint CAS or observes exactly next under a row lock. The original capsule, original record, FDB checkpoint/history and intent removal commit together in the existing FDB activation transaction.

No store read reconstructs FreshClaim, FreshAdmission, DispatchPermit, an owner approval, a settlement witness, or a provider attempt. This maintenance recovery never calls a provider, uploads ciphertext or publishes an envelope. Original relay consumption/Accepted recovery remains separate. A source change, revoked device, missing evidence, changed prior/root/stage, expired output deadline or corrupt intent refuses activation. A referenced stage is retained by GC until reconciliation; an unproven intent is not silently discarded to continue. Reconciliation after changed source or expired output needs a separately proven cancellation/rebase path and remains incomplete.

The deterministic test cuts suppress FDB activation after a known real SQL commit; they are not PostgreSQL wire-level commit-unknown injection. The actual-service journey now contains both Review and FileDoc cuts, cold reopen, exact original capsule/record/wire/checkpoint assertions, and missing/corrupt-evidence refusal. Existing lost relay ACK, provider-count and single-settlement assertions remain in the journey. Source-only at initial publication: these additions still require compiler, Clippy and the full isolated-services Runtime batch. No iPhone or production acceptance is implied.
