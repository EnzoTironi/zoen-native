## Known blockers to fix first

1. **Plan mutation/restore/Undo race.** Native and Android re-read admission/hash then call an old writer through a second Engine lock. Network writes can occur between those operations. Make the existing canonical edit/toggle/add/remove/Plan-restore APIs require the observed hash and validate ready/admission/hash under the same lock as mutation. Update all Rust/Swift/Kotlin callers and tests atomically; do not add `From` aliases. Restore UIs must retain the hash from opening confirmation. Undo must bind the resulting mutation and reject intervening edits. The pending-to-confirmed hash representation changes on a pure acknowledgement; choose a stable result binding instead of a false mismatch. Relevant clients: `PlanPageScreen.swift`, `VersoesView.swift`, Android `PlanPageView`, `PageSaveCoordinator`, `ItemScreen`, `VersionPreview`, `ZoenViewModel.undo`.
2. **Web checkpoint history validation.** `crates/zoen-web-core/src/client.rs` compares only the current epoch digest. Persist and compare digests for already-held epochs across reload, and verify checkpoint `upto.seq/hash` against the local chain as required by ADR 0026. Add conflicting old-epoch and wrong-prefix cases before browser messaging acceptance.
3. **Portable snapshot owner binding.** `ExternalDevice::load` checks ciphersuite but not the active own leaf's credential/signature key against its certified signer. Reject snapshot A with signer B before seal/open. This is an independent source finding, not a claimed remote exploit.
4. **FetchLink delivery loss.** Relay `db::take_link_box` uses `DELETE ... RETURNING sealed` before receipt. A lost response permanently loses the box. Implement idempotent retrieval with authenticated receipt, TTL and device binding; test response loss/retry, wrong device and expiry. Do not weaken enrollment authority.
5. **Complete current Core/CLI validation and hosted import failure.** Finish all 231 cases and both real-relay CLI journeys under unchanged budgets. PR70's hosted missing `plan.md` is not proven fixed by the new import wait or the earlier local pass.
6. **Bindings and bounded native callers.** Generate Swift/Kotlin/JNI from one stable current Core composition. Native file preflight currently reads `core.item(...).file` then calls the old `fileBytes`; the local check cannot protect against underdeclared remote cached BLOBs. Historical previews remain blocked. Android's three current readers use the new bounded API, but `VoiceTransport.localFile` still uses unbounded caller reads/raw media/path/name fallbacks. Migrate callers and remove obsolete interfaces together.
7. **Web outbox edges.** Only stale MLS seals should block an epoch; other temporary rejections need bounded durable backoff. Refuse duplicate pending invite publication. Remove the unpublished invite `serde(default)` transition. Cold-restore the pre-ack `sending.snapshot`, emit identical ID/signature/ciphertext and confirm once.
8. **Actual client acceptance.** Run current native attachment review/preview/cancel/send/reopen and historical reception; add the compressed >16 MP Android fixture without a full-size allocation; build/test current Kotlin/JNI and API28/API35; build WASM and run the real owned native/browser enrollment, bidirectional messages, reload, reconnect and revocation.
