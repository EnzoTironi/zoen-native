# Shared reply activation

Part of [runtime continuity](shared-runtime-continuity.md), tracked in [#175](https://github.com/EnzoTironi/zoen-native/issues/175) and [#327](https://github.com/EnzoTironi/zoen-native/issues/327). Product direction: Enzo; technical requirement and implementation: Codex.

A qualified shared route can activate an already incurred native text result. The original native signing engine, complete encrypted capsule, SQL directory admission and finite activation window are reused. One shared transition advances the existing native-root and captured-result subjects together with the exact original publication metadata. No queue, balance or second publication authority is added. Per-run/device leases, the current source frontier and retained capture are checked before preparation and again in the activation transaction. Unannotated shared output admission refuses.

Shared publication metadata retains the intended checkpoint sequence; its digest resolves from the existing independently authenticated effect history. This avoids a self-referential checkpoint hash while preserving the original encrypted metadata bytes. SQL/FDB cuts and lost/late known acknowledgements recover the same pending native image and wire, using a fresh certified-directory admission. Source advancement may retain the inert original; it cannot authorize relay transport. Clean missing publication/history refuses rather than rebuilding it. Later financial ACKs refine the same captured-result subject without rewriting the publication. Archived history observation remains read-only after generation retirement and cannot acquire an old effect guard.

Productive model execution, negative resolution of an unactivatable pending operation, and complete deployment restore/takeover remain unqualified. In particular, revocation before recovery can leave the original pending and closed; this implementation does not erase it or infer a refund. Manual iPhone and public-provider acceptance remain separate.


A qualified shared route can deliver the already activated original through the production relay handlers. The same current directory/source/run/device checks, independent one-use effect consumption and atomic source fence apply. Shared checkpoint history carries encrypted native facts, so its relay record bound derives from the trusted anchor profile (32,768 bytes for Runtime, 4,096 for Images), never a caller flag. Original wire and history digests remain exact.

Historical receipt and intermediate-prefix activation use the same native proof/transaction checks as Images. The existing checkpoint advances the native root and, for acceptance, refines the captured-result subject with the original receipt ciphertext. The original is authenticated before either store commit; the stage is pinned, and a fresh transaction rechecks the same live proof after that pin. Recovery takes a fresh device lease and verifies the exact native image, publication and actual source positions. It does not acquire a new send grant, call the provider, reconstruct missing bytes, or require renewed directory permission to recognize an already accepted response. Revocation still prevents new transport.

Automated coverage includes receipt/prefix cuts before pin, before SQL, after SQL, after FDB and after acknowledgement; later source appends; byte-identical receipt recovery; missing-receipt refusal; later financial acknowledgements; and genuine lost WebSocket acknowledgement followed by historical recovery after device revocation. Tests use actual PostgreSQL/FoundationDB and production loopback HTTP/WebSocket handlers. This is not iPhone acceptance, public-provider readiness or complete deployment restore.
