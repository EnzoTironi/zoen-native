# Private closed-group relay

The private adapter supports Direct and Group chats with Closed or EndToEnd
privacy through trusted service bindings. Its caller supplies authenticated
identity/device context and scoped directory facts. It does not establish public
authentication or complete encrypted sync. The existing `ClosedSpace` class,
namespace, migration and version-1 closed-group state remain compatible.

Shared Rust verifies Publish frames, certificates and signatures, applies the
native admission rules, normalizes invite capabilities and produces canonical
Sequenced protobuf bytes, chain hashes, membership and delivery audience. JavaScript
provides bounded persistence and invokes those Rust exports through precompiled
WASM with `initSync`; it contains no second crypto, protobuf or admission policy.

After verification, one synchronous SQL transaction looks up the original receipt,
loads projection/history/invite facts, admits a fresh event and commits its bytes,
projection and invite consumption together. Valid retries return their original
receipt with the current audience, including after removal or changed signed retry
bytes. Admission refusal cannot add an event or change membership. A valid refused
publication or duplicate may advance safe retention compaction, as in the native
log; a later SQL failure rolls the entire transaction back.

`SpaceStorage` shares persistence helpers with the original storage-only Worker;
neither helper owns a nested transaction. `ClosedSpace` uses a separate Durable
Object namespace and exposes no raw `appendAdmitted`. Its private bounds retain
Space IDs up to 128 characters, client IDs up to 256, and lowercase author/hash
keys; this is not complete native LogStore equivalence.

## Reproduce locally

Use the [admission toolchain](admission.md#reproduce), pinned Cloudflare dependencies
and an existing development FoundationDB cluster with `FDB_CLUSTER_FILE` and its
client-library environment configured. From the repository root:

```sh
npm ci --prefix infra/cloudflare
cargo test --locked -p roda-relay-admission
cargo clippy --locked -p roda-relay-admission --all-targets -- -D warnings
cargo clippy --locked -p zoen-relay --example cloudflare-closed-fixture -- -D warnings
CARGO_BUILD_JOBS=2 node scripts/verify-cloudflare-closed.mjs \
  --out-dir .dev/cloudflare-closed
```

The runner builds current WASM, creates and cleans a fresh isolated native FDB
cell, and compares exact receipts, rejection reasons, audiences and membership
against SQLite Durable Objects in local workerd. `summary.json` records hashes and
source provenance. `--skip-build` reuses WASM; the fresh native FDB oracle still runs.

The current local oracle exercises 17 original closed-group differential steps,
four unsupported/signature cases, and 302 additional encrypted Direct/Group
transitions. The actual signed MLS envelopes are generated by real
`roda_mls::Device` instances and successfully decrypted on peers 275 times.
The eight adapter tests also cover persisted workerd restarts, racing identical
commits, and rollback after late invite/pruning writes fail. Four original SQL
storage contracts remain required. Source and artifact hashes are written into
`summary.json`; this local proof does not establish remote acceptance.

## MLS epochs and retention

`roda-relay-admission::mls_projection` now owns the native and portable transition
plan for current epochs, last committing device, added-member holds, joining-device
holds and checkpoints. The native adapter persists that plan in its existing FDB
transaction and key layout. The private Worker persists the same plan alongside
the event in the existing opaque projection, without a second Space authority.

The native admission rules still require current epochs for commits and encrypted
applications, and allow a Welcome to another device of the same identity only
under the native device/commit rules. The oracle checks real device joining and
Welcome processing, two competing commits, stale commit/application refusal,
member removal, and a cold native FDB epoch reload. Direct chats retain their
two-identity and no-invite constraints. Public/Community Spaces remain refused.

Every current identity must have a retained hold before pruning starts. Live
device holds determine the floor; the native 30-day device ceiling and optional
`ZOEN_PRUNE_CEILING_SECS` override are shared. One transaction scans at most 256
entries and rewrites only digest-authenticated ciphertext stubs, preserving
sequence, predecessor, chain hash and author/client-id receipts. The host loads
one ciphertext at a time. The oracle exceeds one batch and compares every stored
byte and the exact original stub returned on retry. Plain and legacy ciphertext
without a prunable digest retain their original bytes.

The native fixture uses a fresh `qa_mls_v105_*` cell, asserts its ownership before
reads/cleanup, drops that cell and verifies its exact prefix is empty. It neither
starts nor reconfigures the development FoundationDB service.

## Private deployment and remote proof

`wrangler.closed.jsonc` disables public routes, Workers.dev and preview URLs. Its
build hook resolves the repository-root `build-cloudflare-closed.mjs` wrapper,
which fixes the working directory and generates current WASM without FoundationDB.
Both repository-root and npm-workspace deployment dry-runs passed.

Private Worker `zoen-relay-closed`, version
`b5a34a7e-4305-46de-b595-06a909864e8a`, passed authenticated service-binding QA:
11 pre-invite native steps, six events totaling 4,608 canonical bytes, invalid
signature rejection, payload refusal, exact replay across two preview **client**
sessions, and seven private HTTP paths returning 404. Both clients stopped.
This did not force a remote Durable Object restart or exercise remote invite clocks.

The opt-in helper is `relay-state/tests/closed-remote.mjs`; it requires
`ZOEN_CF_REMOTE_CLOSED_QA=1` and `ZOEN_CLOSED_FIXTURE` pointing to a fresh paired
native fixture. Its static allowlist permits only that synthetic Space.

Machine-local receipt
`/private/tmp/zoen-cloudflare-admission-v96/validation/closed-acceptance.json`
has SHA256 `524a38f64b3572e51a6d94b77f022bc5f203668958a4032ce03d28a2157b3d82`.
All 32 recorded source hashes match `c7de156f`. These temporary paths are not
portable CI proof. Later [CI run 39215512310](https://github.com/EnzoTironi/zoen-native/actions/runs/39215512310)
passes the closed-group differential lane at head `f43b23f3`; that CI attribution
remains separate from the earlier remote proof.

Next gates are transactional composition with Directory identity/revocation
authorization, global invite resolution, the public WebSocket protocol and
delivery, public media integration and backup recovery. MLS projection parity
here covers the private Direct/Group persistence boundary; it does not accept
those public flows. The separate
[private R2 media adapter](relay-state/MEDIA.md) has bounded real encrypted-object
proof; it does not establish public sync, transfer or backup recovery acceptance.
